# Основание

Рабочее место сотрудника банка для проверки комплектности документов по конкретному запросу к бизнес-клиенту. Версия 0.1, 6 октября 2026 года. Команда: Super_Бобры.

[Рабочее демо](https://osnovanie-super-bobry.bu-rchfieldadams12.chatgpt.site) · [Презентация](https://osnovanie-super-bobry.bu-rchfieldadams12.chatgpt.site/osnovanie.pdf) · [Материал для контактов в банке](https://osnovanie-super-bobry.bu-rchfieldadams12.chatgpt.site/bank-brief.pdf)

## Что открыть

- `app/` — работающий локальный прототип и тесты.
- `demo.html` — самостоятельное демо, открывается в браузере без сервера. История в нём ограничена текущей вкладкой.
- `application.md` — тексты всех полей заявки со скриншотов.
- `research/decision-log.md` — выбор из шести гипотез, источники, границы подтверждения.
- `research/validation-plan.md` — интервью, запрос агрегатов, критерии продолжения и отказа.
- `research/bank-brief.pdf` — двухстраничный материал для первого знакомства с банком.
- `research/contact-kit.md` — готовые обращения, сценарии встреч по ролям, запрос минимальных агрегатов и ответы на вопросы контактов.
- `model/financial-model.md` — экономика, сценарии и формулы. Пересчёт доступен в приложении.
- `architecture.md` — интеграция, защита данных, ограничения и масштабирование.
- `roadmap.md` — работа до финала и банковский пилот.
- `pitch/` — презентация, речь, сценарий демонстрации и ответы жюри.

## Запуск

Нужен Python 3.10+; внешних Python-пакетов нет.

```sh
cd app
python3 server.py
```

Откройте http://127.0.0.1:8765. После перезапуска сохранённые версии остаются в `app/.data/demo.sqlite`. Для другого пути задайте переменную `OSNOVANIE_DB`. Сервер слушает только loopback.

```sh
python3 -m unittest -v test_engine.py
```

Пример JSON можно импортировать из `app/example-initial.json` и `app/example-corrected.json`. Вкладка «Документы» принимает TXT с полями «Тип», «Номер», «Договор», «ИНН контрагента», «Сумма». Это открытый формат демонстрационного текстового входа. Универсального распознавания произвольных сканов в этой версии нет.

Полный набор проверок: `python3 -m unittest -v test_engine.py test_server.py`. Обновление самостоятельного демо: `python3 build_portable.py` из `app/`. Python — эталон серверных правил, JavaScript — адаптер браузерного демо; совпадение результатов проверено на 100 синтетических вариантах. При изменении правил нужно повторить сравнение обеих версий, включая граничные случаи сумм/форматов.

## Основной сценарий

1. Открыть исходный комплект: три операции, пять документов.
2. Проверить. Найдутся четыре замечания: разница сумм, недостающий акт, другой ИНН, отсутствие подходящего договора.
3. Открыть ссылку на строку документа. Проверить сформированный проект уточнения.
4. Открыть дополненный комплект и проверить: замечаний по профилю нет.
5. Оставить комментарий и зафиксировать проверку комплектности сотрудником.
6. Скачать отчёт; открыть историю версий.

## Граница готовности

Реализован функциональный прототип основного сценария на синтетических данных. Реальные интервью, замеры времени, оценка качества на банковских документах и промышленная интеграция ещё не проведены. Названия компаний и ИНН в примерах вымышлены, контрольные суммы ИНН не проверяются. Результат `complete` означает полноту только по выбранному демо-профилю. Подписи, подлинность, экономический смысл и правомерность операций проверяет уполномоченный сотрудник.

Проверка сотрудника в демо не содержит аутентификации, поэтому запись показывает сценарий взаимодействия, а не юридически значимое подтверждение. SQLite хранит снимки; хеш позволяет идентифицировать содержимое, но не защищает журнал от администратора. До использования клиентских данных необходимы банк, согласованный контур, SSO/RBAC, защищённое хранилище, политика доступа и проверка ИБ.

## Публикация материалов

Для заявки подготовлены публичные ссылки на презентацию, демо/видео, репозиторий и аналитику; они перечислены в `publication.md`. Пакет не отправляет документы в облако и не отправляет сообщения клиентам. Для внешнего демо используйте только синтетический набор. Доступ подтверждается конфигурацией аудитории и статусом публикации; скачивание из аккаунта организатора отдельно не проверялось.

## Проверка гипотезы

Существование проблемы общения по документам подтверждено рекомендациями Банка России. Высокая частота проблемы именно в процессе МСБ и эффект продукта пока являются гипотезами. Следующее решение о развитии принимается по интервью и ретроспективе. При отрицательных результатах меняется процесс/сегмент или проект останавливается; удачный интерфейс сам по себе не подтверждает спрос.
